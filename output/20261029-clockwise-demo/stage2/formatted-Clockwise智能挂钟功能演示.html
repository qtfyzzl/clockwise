一、项目概述

Clockwise 是一款基于 ESP32 的开源智能挂钟固件，驱动 64×64 全彩 LED 点阵面板（HUB75 接口）。设备以 32 厘米见方的像素化画面同时承担时间显示与视觉装饰两种角色，支持联网对时、主题切换、亮度自适应与空中升级。

本项目在开源原版的基础上完成了面向实际使用的系统性改造，核心变化集中在三个方面：主题体系从"单一主题"扩展为"原生 + 画布双引擎"、配置界面全面中文化并做了传输优化、补齐了 OTA 空中升级与离线兜底等工程化能力。

三、核心功能详解

3.1 双主题引擎

原版的架构约束是"同一份固件只能编译进一个主题"，切换主题需要修改工程配置并重新烧录。本项目将其改造为运行时可选的双引擎结构。

画布模式（Canvas） 面向自定义需求。主题以 JSON 文件描述，包含背景色、静态元素、精灵序列与动画参数。用户在设置页上传 JSON 即可生效，设备将其存入内部闪存，断网状态下同样可用。

原生模式（Native） 面向性能与画质。主题的图像资源以 RGB565 原始像素数组编译进 Flash，运行时直接从内存映射区读取绘制，不经过解码流程。

两种模式的资源占用差异显著：

项目画布模式原生模式差值
空闲堆内存82.9 KB128.9 KB+46 KB
最大连续块41.0 KB86.0 KB+45 KB
单主题 Flash 占用2–14 KB约 11 KB—

差异主要来自画布模式必须常驻 48 KB 的 PNG 解码缓冲。这也解释了为什么复杂主题在画布模式下难以承载，而原生模式可以轻松运行。

切换在设置页完成，引擎清单由固件动态上报，新增原生主题无需改动前端。

3.2 主题体系与内容生态

当前设备内置 20 个主题，分为两类：

画布主题（18 个） 包括吃豆人、彩虹猫、圣诞史努比、星际大战、复古电脑、多种角色插画等。每帧图像为 8-bit RGB 编码的 PNG，单帧解码后不超过 4 KB。

原生主题（2 个） 为马里奥与吃豆人，均为社区经典主题的固件内置版本。

主题引擎对图像格式有明确要求，这些约束来自设备端的实际解码能力：

约束项要求违反后果
文件格式仅 PNGJPEG 等格式无法解码
位深8-bit1/2-bit 索引色会导致设备反复重启
单帧体积≤ 4096 字节超出则跳过该帧
主题文件≤ 16 KB超出则无法解析

3.3 空中升级

设备采用 A/B 双分区方案，新固件写入空闲分区，校验通过后才切换启动项。任何一步失败都保持原分区启动，不存在因升级失败而变砖的风险。

分区布局如下：

分区偏移大小用途
nvs0x00900020 KB用户设置
otadata0x00E0008 KB启动分区记录
app00x0100001.81 MB固件槽 A
app10x1E00001.81 MB固件槽 B
spiffs0x3B0000256 KB主题存储
coredump0x3F000064 KB崩溃现场

升级提供两条通道：

网页上传 在设置页选择固件文件，页面显示实时进度，传完自动重启，全程不依赖电脑端工具。

命令行推送 适合开发调试，一条命令完成，配合固件内置的 mDNS 可直接用主机名寻址。

实测数据表明该链路效率可观：

次数耗时平均速率结果
第一次32.5 秒52.2 KB/s校验通过
第二次20.4 秒85.0 KB/s校验通过
第三次32.8 秒53.0 KB/s校验通过

三次升级分别写入不同分区，验证了双槽轮换的可靠性。升级前后主题存储占用完全一致，说明分区隔离有效。

3.4 中文设置页

设置页是设备的主要交互入口，全部界面中文化，采用单页应用结构，分为显示、时间、主题引擎、画布主题、固件升级五个分组。

为保证弱网环境下的可用性，做了三项针对性优化：

预压缩传输 页面在编译期以 gzip 压缩，32 KB 源文件压缩至 13.5 KB，传输量减少约 58%。

非阻塞写入 响应采用分块写入并设置超时，客户端不接收数据时主动放弃，不会拖住主循环。

请求串行化 单连接服务下将并发请求排队，避免请求互相踩踏。

页面还内置主题预览功能：上传主题后可即时看到 64×64 的渲染效果，无需等待设备重启。

3.5 离线兜底

设计上假定网络随时可能不可用。当设备启动后 20 秒仍未连上网络，屏幕自动切换为简约数字钟：

  • 四位数码管风格的大号数字，占满屏幕宽度
  • 底部一行小字标注"no wifi"
  • 时间来源为闪存中保存的最后一次同步值，配合运行时长推算

设备的 WiFi 模块在离线状态下每分钟重试一次连接，同时保留配网热点，手机可随时连入重新配置网络。这一设计使设备在路由器重启、密码变更等常见场景下能够自行恢复。

3.6 显示与功耗管理

自动亮度 通过光敏电阻感知环境光，将读数线性映射到面板亮度。实现中包含三项防护：双端钳位防止读数越界导致亮度跳变、上下限相等时按最亮处理避免除零、迟滞比较避免临界点反复切换。

时间持久化 设备无电池 RTC，断电后系统时间会归零。固件每 30 分钟将当前时间写入闪存，重启后若网络未就绪则用该值恢复，使离线画面仍能显示大致正确的时间。写入采用单键更新，避免为保存一个时间戳而重写全部配置项。

四、技术架构

4.1 分层结构

固件采用三层结构：应用层负责启动流程与主循环调度，基础服务层提供网络、配置、Web 服务与状态提示，主题层实现具体的画面渲染。两层主题引擎共享统一的时钟界面接口，应用层通过工厂方法在运行时实例化其中一个。

4.2 内存分配

ESP32 的 320 KB 可用 RAM 需要同时容纳协议栈、图形缓冲与应用数据，分配情况如下：

项目占用占比
静态变量61.6 KB19.3%
PNG 解码缓冲（仅画布模式）47.0 KB14.7%
主题 JSON 缓冲16.0 KB5.0%
空闲堆82.9–128.9 KB26%–40%

其中图像解码缓冲必须在 WiFi 启动前抢占，否则协议栈初始化后堆内存碎片化，大块分配会失败。

4.3 稳定性设计

改造过程中定位并修复了若干会导致设备不可用的问题，这些问题在功能演示中构成了可靠性基础：

问题现象处理
索引色图像崩溃设备无限重启强制 8-bit RGB，加载前校验
闪存自动格式化主题全部丢失改为手动触发，并给出界面提示
超大主题卡死设备无响应，串口无输出加载前按容量拦截，不再回落远程
引擎切换失效设置不生效补齐参数写入分支
图片超限越界读部分主题图片不显示补充尺寸与长度校验

其中"超大主题卡死"的根因链条值得记录：主题文件超出解析缓冲后解析失败，旧逻辑会转而从远程服务器拉取同名主题，而远程 TLS 握手不受超时控制，最终阻塞主循环。当前版本在文件大小层面就做了拦截，不再触发远程回落。

五、工具链

围绕主题制作与维护，配套了完整的工具集：

工具用途
主题校验检查 JSON 结构、图片格式、体积与引用完整性
格式转换将不合规图像重编码为设备支持的格式
画面预览在电脑上渲染主题效果，烧录前核对
批量上传按名单同步主题到设备
页面打包将设置页压缩为固件可内嵌的数组
桌面设计器图形化编辑主题，输出规范 JSON

工具之间存在明确的职责边界：校验工具负责发现问题，转换工具负责修复，设计器负责创作。三者共享同一套图像编解码实现，避免因实现不一致导致的反复。

六、使用指南

6.1 首次配网

设备上电后若未保存网络信息，会自动开启名为 Clockwise-Wifi 的配置热点。手机连接该热点后访问 192.168.4.1，选择目标网络并输入密码即可。设备同时支持通过串口以 Improv 协议推送凭据，适合批量部署场景。

6.2 更换主题

进入设置页的主题分组，画布模式下列表展示设备内已有主题，点选即可切换；原生模式下展示固件内置的引擎，切换后重启生效。

上传新主题时选择 JSON 文件，填写主题名后上传。系统会在上传前校验文件大小，超过 16 KB 的主题会被直接拦截并提示精简建议。

6.3 升级固件

设置页最下方的固件升级分组，选择 bin 文件后上传，页面显示百分比进度，完成后设备自动重启。升级期间请勿断电。

七、后续规划

主题容量扩展 现有 8 个主题因文件体积超出解析缓冲而无法使用，包括马里奥、桃子公主等系列。可选路径包括：精简帧数至体积达标、将图像资源外置为独立二进制文件、或将这些主题转为原生模式实现。

原生主题补充 上游尚有 4 个原生主题未集成（文字时钟、世界地图、恶魔城、宝可梦图鉴）。当前固件余量约 154 KB，按单主题 10.9 KB 计算完全可容纳。

图像转换工具 计划在桌面设计器中增加 RGB565 导出能力，使任意图像可一键转为可编译的固件资源，进一步降低原生主题的制作门槛。

八、结语

本项目在保持原有硬件平台与开源协议的前提下，完成了从"能跑的示例"到"可日常使用的产品"的转变。核心工作围绕三条主线展开：以双引擎解决主题能力的天花板问题，以 OTA 解决维护成本问题，以一系列边界防护解决稳定性问题。

当前设备已稳定运行，20 个主题、两种渲染模式、无线升级与离线兜底均已可用。后续将重点推进主题容量扩展与制作工具链的完善。
