
## 10-29 上午：主题全丢 + snake-text 闪退（重大发现）

### 主题全丢的原因
`SPIFFS.begin(true)` 第二个参数 = **挂载失败就格式化**。用户换 USB 口时电源闪断，
正卡在写文件 → 分区损坏 → 下次启动自动格式化 → 25 个主题清零（151,353 → 12,801 字节）。
NVS 里的 WiFi 也退回旧值。**教训：这种"自动格式化"设计会把用户数据全清，至少要打日志/提示。**

### snake-text.json 闪退根因（关键）
```
Guru Meditation Error / BREAK instr / EXCVADDR 0xffffffe0 / A0=0x00000000 / Backtrace 只有一层
```
**根因：图片是 1-bit / 2-bit 索引色（调色板）PNG，PNGdec 1.0.1 位解包有缺陷，跳到空指针。**

实测对照（这是判定标准）：
| 主题 | 格式 | 结果 |
|---|---|---|
| pac-man | 8-bit RGB | ✅ |
| nyan-cat / christmassnoopy | 8-bit RGBA | ✅ |
| keqing-1 / kuromi-1 | 4-bit 调色板 | ✅ 官方在用 |
| snake-text | **1/2-bit 调色板** | ❌ 闪退 |
→ 不是"调色板不能用"，是**位深 1 和 2 有雷**。

### 新增工具

  34 个主题跑过，判定可靠。

### 抢救流程（设备卡在崩溃循环时）
趁崩溃窗口 `POST /set?canvasFile=__none__`（指向不存在的主题）→ 重启后不加载坏主题 → 设备稳定 →
再上传主题、改回正常主题。实测 45 次重试内第 1 次就成功。
